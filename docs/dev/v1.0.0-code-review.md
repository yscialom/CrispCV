# v1.0.0 Code Review & Release Prep

This document tracks findings, suggestions, and verification steps for the v1.0.0 release of CrispCV.

## General Observations

The application is in a very strong state. It adheres to modern Angular practices (Signals, Zoneless, OnPush) and the code structure is clean and modular. The documentation is comprehensive and mostly up-to-date.

## Codebase Analysis

### Strengths

- **Architecture**: The separation of concerns is excellent. `ResumeDataService` acts as a solid single source of truth using Signals.
- **Modularity**: Components are small, focused, and use `OnPush` strategy.
- **Extensibility**: The profile registry generation script (`tools/generate-profile-registry.js`) is a clever way to handle multiple languages dynamically.
- **Type Safety**: strict TypeScript configuration is well-enforced.

### Issues / Improvements

- **Data Model**: `DurationUtils.parseDate` uses loose regex matching. While robust, strict ISO-8601 enforcement at the data level would be cleaner.
- **Typo in Profile**: `config/profile.en_US.ts` contains the word "risques" (French) in the English profile description for Natixis.
- **Placeholder Data**: `config/profile.en_US.ts` contains placeholder URLs (e.g., `https://bcert.me/example`). These should be removed or commented out before release if this file is intended as a template.
- **Clipboard API**: The "Copy Permalink" feature (`ResumeEntryComponent`) uses `navigator.clipboard.writeText`. This API is only available in Secure Contexts (HTTPS) and `localhost`. While GitHub Pages provides HTTPS, users deploying to other non-secure environments might face issues. A fallback or a check `if (navigator.clipboard)` might be beneficial, though low priority for v1.0.0 given the target audience.

## Documentation Review

- **`docs/dev/GEMINI.md`**: Contains a few typos ("developpers", "minde").
- **`README.md`**: Clear and helpful. The "Quick Start" section is excellent for new users.
- **Specs**: The specs align well with the implementation.

## Usability & UX

- **Permalinks**: The deep-linking feature works well conceptually. The smooth scrolling (configured in `app.config.ts`) provides a nice user experience.
- **Localization**: Date and number formatting is handled correctly via `Intl`.
- **Responsive Design**: The sticky navbar and mobile menu logic (`NavbarComponent`) seems robust, handling edge cases like scroll hysteresis and dynamic height.

## Recommended Complex Tests

Before releasing, perform the following manual or automated verification scenarios:

### 1. Cross-Browser & Device

- **Mobile Safari (iOS)**: Verify the "sticky navbar" and "hamburger menu" behavior. iOS Safari has dynamic viewports that can sometimes mess up scroll-based logic.
- **Android Chrome**: Verify the same.
- **Firefox**: Check for scroll snapping or smooth scrolling quirks.

### 2. Deep Linking & Routing

- **Cold Boot with Fragment**: Open a fresh incognito window with a URL like `http://localhost:4200/experience#capfi-2023-05-1`. Verify that:
  1. The app loads.
  2. It navigates to the Experience page.
  3. It scrolls down to the correct card.
  4. The card is highlighted.
- **Language Switch Persistence**: Change language to French, close the tab, reopen. Verify it stays in French.

### 3. Edge Cases

- **Missing Dates**: Test an experience entry with only a start date (already handled, but check visual output).
- **Special Characters**: Add a company name with accents or symbols (e.g., "C++ Company") and verify the permalink generation is valid and functional.
- **Zero Duration**: Test an experience starting and ending in the same month.

### 4. Printing

- **Print Styles**: Press `Ctrl+P`. Ensure the resume prints cleanly. The sticky navbar should ideally be hidden or non-sticky in print mode. Background colors might disappear (browser default), so ensure text contrast remains high.
